  1. **`long` is 32-bit on the ESP32, so the clipping code can overflow on the device and the tests cannot see it.**
     - Files: `firmware/src/core/canvas.c:48` (`long x1 = (long)x + w - 1`), `:117` (`(long)y + h - 1`), and `:124` and `:157` (`(long)ceil(...)`). The host tests run with 64-bit `long`, so they cannot catch this.

     - On the device, `XFillRectangle(x >= 2, ..., w = 0x7FFFFFFF)` overflows. Signed overflow is undefined and in practice wraps negative, so nothing is drawn. Real X would paint the whole right side.
     - Pyro appears to pass non-negative sizes, so this is latent rather than hit today. It matters for the "huge sizes must clip" focus item.
